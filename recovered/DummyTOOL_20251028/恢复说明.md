## 已核实的反编译修订

直接导出的代码可以通过语法解析，但部分语句运行时会出错，因此另建 src/。本次只按原字节码恢复表达式和分支，没有对旧控制协议进行改造。

1. 恢复 14 处切片，例如错误导出的 parts[1[:None]] 应为 parts[1:]。原字节码均是“容器、起始值、结束值、BUILD_SLICE、BINARY_SUBSCR”。
2. 恢复 ActionManagerWindow.on_execute_action() 的分支。原字节码在录制状态为假时跳到偏移 24，读取当前选中动作；导出代码却把这一部分放在了 return 之后。
3. 恢复 dummy_set_PID() 的冷却判断、CMDMODE 分支和参数处理。原字节码在普通状态下从偏移 34 继续处理按钮，CMDMODE 分支结束后返回，其他按钮从偏移 112 处理参数。
4. 恢复 dummy_move()、dummy_button_history_pos()、dummy_button_action()、dummy_button_handoffset() 的冷却分支。原字节码允许“未处于冷却”或“关闭防呆”时继续处理。
5. 恢复 uni_send_data() 的串口判断。原字节码要求串口对象存在且已打开，才能从偏移 34 继续发送。

具体改动见 evidence/repairs.diff。离线校验确认所有模块的字符串和资源常量与直接导出版本一致，中文未通过脚本替换。

## 与当前固件的已知差异

| 旧上位机行为 | 当前项目源码或恢复检查结果 |
|---|---|
| 手爪使用 !HAND_O、!HAND_C、!HAND_EN、!HAND_DIS、!HAND_POS、!HAND_I、!HAND_ZERO | 当前 REF 协议使用 !HD_*，需要适配 |
| 录制前发送 !DISABLED | 当前 REF 对外处理的是 !DISABLE；录制流程需要重新设计 |
| 坐标解析依赖小写 ok 后跟 6 个数字 | 当前 REF 返回 GetJPos OK ... H:... 或 GetLPos OK ... H:...，旧解析器无法直接识别 |
| 世界坐标页 PAUSE 按钮 | 旧代码只打印“暂停操作 功能待开发”，没有实现当前固件的暂停与恢复流程 |
| 示教按固定时间间隔发送点，默认 200 ms | 没有按新版任务完成响应逐条确认，需要与当前队列及异常状态协议衔接 |
| 按钮冷却会统一阻挡操作 | 旧上位机 STOP 也可能被冷却拦截，未具备当前要求的上位机最高优先级处理 |

以上是静态源码对照结果，不能代替实机验证。当前恢复代码尚不能直接作为新版机械臂的正式控制端。
