# 机械臂控制升级说明

版本：上位机 0.2.0，REF 主控 1.1.0。更新日期：2026-11-17。

## 状态与指令

| 指令 | 行为 |
| --- | --- |
| `!START` | 检查节点在线，广播使能机械臂和手爪，回零点姿态 |
| `!STOP` | 优先锁存急停，发送全节点零速度制动，保持使能，保留当前目标与剩余队列 |
| `!PAUSE` | 立即报告暂停状态，当前已执行指令完整完成后等待；保持使能 |
| `!RESUME` | 返回原状态，清除停止标记；急停续跑被打断目标，暂停继续下一条 |
| `!HOME` | 已使能时运动到工作姿态 |
| `!RESET` | 已使能时回零点姿态，保持使能 |
| `!CLOSE` | 完成回零、检查新鲜位置反馈及完成状态后调用内部 `Disable()` 失能 |

零点姿态为 `(0, -75, 180, 0, 0, 0)`，工作 HOME 姿态为 `(0, 0, 90, 0, 0, 0)`，单位为度。

START 会清除已 HOME 标记。之后首次运动或手爪动作会静默执行 HOME；查询、RGB 和参数操作不触发归位。HOME 标记表示本轮使能后已经完成工作归位，不表示每条指令都先返回该位置。

停止状态为 `EMERGENCY_STOP` 或 `PAUSED`。停止期间允许只读查询和恢复；其余业务返回 `Error: state=...`。重复 STOP、PAUSE、RESUME 返回对应状态；PAUSE 不能把急停降级，STOP 可以把暂停升级为急停。当前指令包含其必要的自动 HOME 步骤。

急停与暂停均保留 FIFO。所有命令模式使用相同的指令完成屏障，下一条运动不会覆盖当前目标。动作入队响应为 `Accepted`，开始执行时报告 `Task Executing`，真正完成后才返回 `OK`。上位机在排队和停止等待期间不消耗动作执行超时。队列最多容纳 16 条等待指令，另有一条正在执行的指令。

`!DISABLE`、`!HD_DIS`、`!HD_EN` 不开放直接执行入口。手爪随整机 START 和 CLOSE 管理使能。CLOSE 遇到 STOP 会等待恢复并重新确认回零，反馈缺失或回零失败时不会失能。

## PIDV 参数

节点 1～6 为关节，7 为手爪。参数顺序统一为 **KP、KI、KD、KV**，值为 0～2147483647 的整数。

```text
#SETPID 1 1000 200 250 80
#SETPID 1 kp 1000
setpid 7 kv 80
#GETPID 1 kp
#GETPID 1
#GETPID all
```

`#GETPID` 不带参数等同于查询全部节点。兼容 `#GET_DCE` 和 `#SET_DCE_KP/KI/KD/KV`。设置操作等待子板保存并回读参数；缺少某参数回包时不以旧缓存填充结果。部分参数已经写入而后续失败时会返回错误，不提供跨参数回滚。

对应上位机接口为 `POST /api/pid` 和 `GET /api/pid?node=1&param=kp`。设置请求示例：

```json
{"node": 1, "values": {"kp": 1000, "ki": 200, "kd": 250, "kv": 80}}
```

单项设置只提供一个键。查询全部节点时省略 node 和 param。

## 偏移及标定

```text
#OFFSET_J 1
#OFFSET_J all
!HD_ZERO
!CALIBRATION
```

`#OFFSET_J all` 依次设置节点 1～7 的偏移，确认子板 Flash 保存完成后重启所有节点和主控。发送失败、保存校验失败或收到 STOP 时不会继续重启；已经写入的节点不会回滚。单节点偏移不自动重启。

维护写入与动作队列互斥，有执行中或等待中的动作时返回 busy。偏移修改会使 HOME 标记失效。

`!HD_ZERO` 依次确认手爪两端限位并记录当前运行时开合角度，结束保持使能。它使用电机堵转反馈，不具备额外夹持传感器；标定应在无物体遮挡手爪的条件下执行。

`!CALIBRATION` 沿用人工对齐到 HOME 后记录偏移、运动到零点姿态、再次记录偏移的流程。运动经过相同的急停恢复状态机，结束保持使能。人工对齐条件由操作者确认，软件无法从编码器推断机械安装姿态。

主控和 35motor、42motor、35hand 子板需要协调升级。新保存确认使用 CAN `0x2b`；旧子板没有该响应时返回保存失败，不盲目自动重启。

## 灯光模式

| 编号 | 模式 |
| --- | --- |
| 0 | 关闭 |
| 1 | 红色常亮 |
| 2 | 橙色常亮 |
| 3 | 黄色常亮 |
| 4 | 绿色常亮 |
| 5 | 青色常亮 |
| 6 | 蓝色常亮 |
| 7 | 紫色常亮 |
| 8 | 自定义 RGB 常亮 |
| 9 | 彩虹流水 |
| 10 | 白色呼吸灯 |
| 11 | 自动跟随工作状态 |

自动模式：待机白色呼吸，机械臂及手爪工作时绿色常亮；任务完成青色慢闪，约 5 秒回待机；急停红色渐亮渐暗快闪；暂停黄色流水。固定模式保持用户选择。RGB 线程独立刷新，不承担在线查询或动作等待，DMA 等待有超时保护。

## 并发通信

真实串口连接默认启用事务编号：

```text
T:123 !STOP
R:123 Stop OK STATE:EMERGENCY_STOP
T:124 !RESUME
R:124 Resume OK FROM:EMERGENCY_STOP STATE:NORMAL
```

手工调试仍支持不带编号的单行指令。USB 在接收中断中扫描完整 STOP 行；UART4、UART5 使用独立高优先级任务扫描接收 DMA。制动任务不等待普通业务队列，动作线程、查询配置线程、RGB 线程独立。

Python 用独立事务订阅等待响应，动作等待不锁住查询和安全指令。动作计时排除停止等待时间；浏览器断开不会清除固件已经受理的运动队列。WebSocket 接收循环不会因等待动作完成而无法接收 STOP。

## 验证范围

测试使用虚拟串口传输和电脑原生编译的真实控制源文件，覆盖暂停边界、急停恢复、自动 HOME、CLOSE 失能屏障、无效输入、PIDV 缺失反馈、偏移保存失败、灯光切换、USB/UART 分包及 WebSocket 并发。

四种固件分别在各自的 `build-control-v1.1` 目录编译；前端构建在 `frontend/dist-control-v0.2.0`。未连接机械臂、未烧录，模拟结果不能证明真实停止时间、制动距离、负载保持能力或回零路径安全。CAN 入队成功也不等同于各节点已经实际使能；这些项目仍需实机验收。
