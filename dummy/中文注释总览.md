# Dummy 机器人固件 · 中文注释总览

> 本文档汇总 `dummy/` 目录下三套 STM32 固件 + 一套 ESP32 IoT 固件的中文注释整理结果：
>
> - `dummy-ref-core-fw/` — 主控板（STM32F4，FreeRTOS，6DOF 运动学 + 通信枢纽）
> - `dummy-42motor-fw/`  — 42 步进子板（STM32F103CB，TB67H450 + MT6816）
> - `dummy-35motor-fw/`  — 35 步进子板（STM32F103CB，与 42 子板代码镜像）
> - `esp32-iot/`         — ESP32 uart-bridge（WiFi → UART 透传 + Web UI + CLI）
>
> **注释原则：仅添加 / 翻译注释，原始代码逻辑零字节改动**（STM32 三套固件已与 `backup/master` 经非注释 diff 校验为 0 行；ESP32 部分含若干兼容性修复，详见第六节）。

---

## 一、注释原则与覆盖策略

| 范围 | 处理方式 |
|---|---|
| 用户编写的业务代码（`Bsp/`、`Ctrl/`、`Port/`、`Robot/`、`UserApp/`） | **加详尽中文注释** |
| ST HAL / CMSIS / FreeRTOS 厂商代码（`Core/`、`Drivers/`、`Middlewares/`） | **不动** |
| 第三方算法库（`Bsp/utils/arm_math/`、`Bsp/imu/MPU6050*`、`mintasca/sca_*` 等） | **不动** |
| 法律文本（GPLv3、ST 版权块） | **不翻译** |
| Doxygen 标签 `@brief / @param / @retval` | **保留英文**（标准语法） |

注释做法：
- 文件头总览 + 函数 / 类语义说明（“做什么、为什么”而不是“怎么写”）
- 关键变量加单位 / 范围 / 约束
- 复杂分支 / 状态机给出意图描述
- 已有英文注释多数翻译；版权 / 法律 / 元标签保留原文

## 二、三套固件硬件与角色对照

| 维度 | ref-core-fw | 42motor-fw | 35motor-fw |
|---|---|---|---|
| **MCU** | STM32F407 @ 168 MHz | STM32F103CB @ 72 MHz | STM32F103CB @ 72 MHz |
| **RTOS** | FreeRTOS（多线程） | 裸机 + ISR | 裸机 + ISR |
| **角色** | 上位机/CAN 主、运动学求解 | 关节电机驱动 | 关节电机驱动（小型号关节） |
| **驱动 IC** | — | TB67H450 双 H 桥 | TB67H450 双 H 桥 |
| **编码器** | — | MT6816 14 bit SPI | MT6816 14 bit SPI |
| **节点 ID** | — | PA8/9/10 三位拨码（0-7） | PA8/9/10 三位拨码（0-7） |
| **通信** | USB CDC + UART4/5 + CAN1 | CAN + UART（调试） | CAN + UART（调试） |
| **控制环** | 多线程 + TIMx | htim4 → 20 kHz | htim4 → 20 kHz |
| **辅助环** | 100 ms 心跳/RGB | htim1 → 100 Hz | htim1 → 100 Hz |
| **持久化** | Flash 末页 EEPROM 模拟 | Flash 末页 EEPROM 模拟 | Flash 末页 EEPROM 模拟 |

35 与 42 子板代码结构镜像一致，主要差异在电机参数（额定电流 / 步进角 / PID 系数）默认配置；软件框架与注释结构完全相同。

## 五、注释风格约定（三套固件统一）

```cpp
// ============================================================================
//  <FileName> —— <一行总结>
// ----------------------------------------------------------------------------
//  - <要点 1>
//  - <要点 2>
//  - ...
// ============================================================================
```

函数级：

```cpp
// <FuncName>: <做什么>。<为什么 / 调用时机 / 关键副作用>。
//   <分点说明>
//   ...
```

类内成员变量：

```cpp
Type name;                  // <语义说明>（含单位 / 范围 / 约束）
```

## 七、本轮额外修复（与注释一并提交）

| 文件 | 修复 | 说明 |
|---|---|---|
| `dummy-42motor-fw/Port/Platform/Memory/emulated_eeprom.h:8` | `#ifndef __STM32_EEPROM_HPP` → `#ifndef __STM32_EEPROM_H` | 头文件保护宏与 `#define` 一致，恢复 `<stm32f1xx_hal.h>` 包含路径，否则 `HAL_FLASH_Program / HAL_FLASH_Lock` 未声明导致编译失败 |
| `dummy-35motor-fw/Port/Platform/Memory/emulated_eeprom.h:8` | 同上 | 同因同治 |
| `esp32-iot/firmware/examples/uart-bridge/mongoose.{c,h}` | 16 字节符号链接占位 → `#include "../../mongoose.{c,h}"` 转发 | 该文件原为 Linux/macOS 符号链接，Windows checkout 落地为纯文本占位致 MinGW 编译失败；改为 C 预处理器重定向后跨平台可编译，行为与原 symlink 等价 |

> STM32 部分：注释整理过程中误将 `H` 写成 `HPP` 引入；已对照 `backup/master` 校正，现工作树非注释代码相对 `backup/master` 差异 = 0 行。
> ESP32 部分：mongoose 占位文件改写仅为修复跨平台兼容，原本在 Windows 下就无法用作 C 源参与构建；ESP-IDF 生产编译路径完全不依赖该文件。

通用编译命令（任选其一目录）：

```powershell
cd dummy/<dummy-xxx-fw>
Remove-Item -Recurse -Force build -ErrorAction SilentlyContinue
mkdir build; cd build
cmake -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Release ..
mingw32-make -j8
```

ESP32 端编译 + 烧录（IDF）：

```powershell
cd dummy/esp32-iot/firmware/examples/esp32/uart-bridge
$env:IDF_TOOLS_PATH = 'C:\Espressif'
powershell -ExecutionPolicy Bypass -NoProfile -Command ". 'E:\ESP\.espressif\v6.0\esp-idf\export.ps1'; idf.py -p COM6 flash"
```
